# Design decisions and proposals

Visual decisions are recorded here with their status. Product or API proposals raised by design work are also recorded here. **A proposal authorizes nothing.** Backend work follows the spec's own process.

## Decisions

| # | Decision | Status |
|---|---|---|
| D1 | Art direction: a dungeon-fantasy world that has evolved into sci-fi mission control ("the dungeon is the computer"). The Tile Pack is the core world asset library, and the world view shows agent activity. This supersedes the "sci-fi ops center" wording in spec §15.4 and closes TILE_PACK_INVENTORY's open next step 2. | **Decided** by the operator on 2026-09-14. Recorded in a §15.4 implementation note. |
| D2 | Reference images stay untracked in `assets/References for Ui/`, described in `references.md`. | **Decided** by the operator on 2026-09-14 |
| D3 | The MVP's "plain inline styles, no design system" ruling (Unit 11, Ruling 4) ends when UI work begins. Its replacement: CSS custom properties plus CSS Modules, with no Tailwind or component library. Adding one needs a recorded reason. | Proposed |
| D4 | Fonts: Pixelify Sans (world and titles), IBM Plex Sans (HUD), JetBrains Mono (telemetry), via `next/font`. | **Decided** by the operator on 2026-09-14 |
| D5 | Figma is the visual source of truth: [AI Command Centre UI](https://www.figma.com/design/3Q5IMyXoPHDBFDv8vjS467/AI-Command-Centre-UI), file key `3Q5IMyXoPHDBFDv8vjS467`. | **Decided** by the operator on 2026-09-14 |
| D6 | Station per Invocation kind: Alchemy = `llm`, Anvil/Workbench = `tool`, Furnace = `deterministic`. | Proposed (presentation only) |
| D7 | Agent identity tints avoid state hues. Status is always an icon and a label, never colour alone. | Decided (accessibility) |
| D8 | World rendering: CSS sprite strips and DOM rooms first. Move to `<canvas>` only if many concurrent animated sprites measurably stutter. | Proposed |
| D9 | World pixel scale per screen. Figma can't rescale pixel art without blurring it, so each scale is its own upload set. At 4× (tile = 192 px) an Overview world fits under 7 tiles across a 1920 px frame. Proposal: **4×** for component docs and the Agents screen's single large room; **2×** for the Overview and Workflows worlds, as a second cut-and-upload pass from `tile-slices.json`. | **Decided** 2026-09-14 (the operator delegated it): 2× for map screens, 4× for close-ups and component docs |
| D10 | Overview mockup rooms at 2× are frames built from the 2× source art, not `Room` instances, because `Room` is 4× only. In code there is one React `Room` with a `scale` prop (2 or 4) and the same `state` variants, so there is no second component. Add a `scale` variant in Figma only if a second map screen needs it. | **Decided** 2026-09-14 (delegated) |
| D12 | "More rooms" on Overview are **system rooms**, never placeholder agents. Goals, Workflows, Approvals, Events and Artifacts each sit on a main corridor, show a real value (or "gated"), and open their screen. The agent wing beside the hub has one room per `GET /agents/active` row and grows with the data. | **Decided** 2026-09-14 (operator asked for more rooms; mapping delegated) |
| D13 | Extra art packs, both confirmed usable in the app by the operator on 2026-09-14:<br>• *Top Down Adventure Pack v1.0* (o_lobster; credit o_lobster)<br>• *Pixel 16 Interiors v2 free*<br>Both are in `assets/gamification/Tile Pack/`. Only props are taken from them. Their walls and floors are excluded because the purple-grey palette clashes with Pixel Crawler teal. Status-coloured or misleading art is excluded: the blue crystal, spikes, enemies, health HUD, outdoor sheets and home furniture. | **Decided** 2026-09-14 (licence by operator; selection delegated) |
| D14 | *Cute_Fantasy_Free* (in `assets/gamification/Tile Pack/`) **may be used**. Its `read_me.txt` licence is non-commercial only, with no redistribution even modified. The operator accepted that on 2026-09-14 ("its fine to use"). **Keep this pack out of any public repo or public bundle, and re-check before any commercial use.** Its style is brighter and outdoor, so it is used for outdoor areas around the dungeon, not inside rooms. | **Decided** by the operator 2026-09-14 |
| D16 | The Overview world is a **scrollable map** larger than the viewport. The operator pans by drag or scroll, and the pan position is client state. A minimap in the world corner shows the whole map and the current view rectangle, and only navigates rooms that exist. The map is 2× pixel scale throughout. | **Decided** by the operator 2026-09-14 |
| D15 | 16 more Pixel Crawler decorations from `Environment/Props/Static` (Esoteric, Dungeon_Props, Furniture), cut by connected-pixel bounds. They are listed in `tile-slices.json` → `extraSlices`, are ambience only and carry no data. | **Decided** 2026-09-14 (operator: "add more if you can") |
| D17 | **Buildings outside the keep** map to real concepts or are unlabelled scenery:<br>• **Project houses:** a village on the west road, one house per `ProjectGoals` row from `GET /goals`. The plate shows `name` and the goal count (capped list, so 500+).<br>• **Registry armory** and **Cost treasury** on the east road, as gated entries to those screens. They show "gated" and no values until their read models exist.<br>• A few unlabelled cottages as ambience only. Never label a building with a feature that doesn't exist. | **Decided** 2026-09-14 (operator asked for houses "for other stuff"; mapping delegated) |
| D18 | **Any art pack in `assets/` may be used, whatever its licence says.** This supersedes the licence cautions in D13/D14 and covers the new *Modern tiles_Free* pack (no licence file). Licence compliance is the operator's responsibility. Practical guard kept: don't publish third-party pack files to a public repo or bundle without re-checking. | **Decided** by the operator 2026-09-14 |
| D19 | **Visual direction: pure pixel keep ("the dungeon/village is the computer").** Adopted after a three-way comparison (cycle 2, `design-reviews.md`).<br>• **Sci-fi is not used by default:** no cyan core, vector conduits, holo brackets or Plex uppercase chrome.<br>• **Chrome is pixel:** bevel frames (2 px outline plus a 2 px edge), dark wood bars and boards, parchment cards, Pixelify Sans for titles, nav, tags and labels.<br>• **JetBrains Mono** stays for raw state tokens, ids, times and long reading text (legibility).<br>• **New Figma colour variables `pixel/*`:** wood-dark, wood, wood-edge, outline, parchment, parchment-shade, ink, label, label-dim.<br>• **State hues are unchanged and reserved for state.** Cyan = active; amber = awaiting approval / pending approval / paused; red = failed or stop; green = done or live.<br>• **The runtime core is pale silver**, and ambient room light is dim neutral warm grey.<br>• **Light is dithered pixel light** clipped to room floors (`assets/gamification/adapted/make-light-pools.ps1`).<br>• **The world is one continuous keep of varied rooms** (`compose-w2-keep.ps1`). | **Decided** 2026-09-14 (operator delegated the choice to visual evidence; critic verdict) |
| D11 | Overview mockup text: agent names are the two real seeded agents. Every other dynamic value is written as its `api.ts` field path (`runs[0].goal.title`, `occurredAt`), so the frame never reads as real data. Counts in the top strip are example row counts. | **Decided** 2026-09-14 (delegated) |

|---|---|---|
| P1 | `GET /agents`: every Agent Definition, not only active ones | An Agents roster that includes idle agents |
| P2 | Model id and provider on `InvocationDetail` | Inspector telemetry; the data exists in the `invocation_started` payload |

| P4 | Artifact browser routes (list, detail with provenance) | Artifacts screen (8) |

| P6 | Event list route with type filter and paging | Events screen beyond the live tail |

| P8 | `activeStop` on `AgentCardData`, or a batched agent-detail read | Overview stop barriers without N `GET /agents/:id` calls |
| P9 | `latestInvocation.kind` on `AgentCardData` | A station per Invocation kind in Overview rooms (D6). Also needs the Tile Pack station sheets sliced, with a slice map recorded. |
| P10 | A person-authored slice map for `Environment/Tilesets/{Floors,Wall,Dungeon}_Tiles.png` | Tile-built room floors, walls, doors and rune sigils. Rooms stay CSS chrome until it exists. **Approved** by the operator on 2026-09-14, as proposed: 34 cuts and 5 exclusions, read back from the Figma page "Tile cut map (review)" into `tile-slices.json` in this skill. The `.aseprite` sources contain no author slices or tilesets. |
